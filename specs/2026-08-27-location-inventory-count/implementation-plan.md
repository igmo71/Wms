# План реализации поячейковой инвентаризации

План является одним крупным вертикальным инкрементом. Этапы нужны для
безопасного порядка изменений, а не для поставки нескольких несовместимых
вариантов процесса. Автоматизированные тесты не создаются и не запускаются.

## 1. Эволюция существующей модели

- Расширить текущий `InventoryCount`, не создавать вторую сущность процесса.
- Добавить обязательную заголовочную ячейку и concurrency token; статус
  `Cancelled` не вводить.
- Сделать фактическое количество строки nullable и разделить ожидаемые и
  добавленные оператором строки.
- Защитить уникальность товара в новом документе именованным ограничением.
- Подготовить прямую новую схему без переходных веток совместимости; тестовые
  данные могут быть очищены.

## 2. Единый серверный жизненный цикл

- Заменить создание пустого документа командой «создать для ячейки».
- В одном контексте захватить документную блокировку и заполнить ожидаемые
  строки из положительных остатков.
- Добавить получение/возобновление активного документа по ячейке.
- Реализовать установку фактического количества, добавление неожиданного SKU и
  удаление ошибочной неожиданной строки.
- Реализовать атомарные проведение и удаление черновика с освобождением
  блокировки.
- Сохранить общий `InventoryPostingService` единственным путём изменения
  остатков.

## 3. Запросы и мобильная HTTP-граница

- Добавить компактные read models документа, строк и итогов.
- Добавить мобильные endpoints списка черновиков, начала/возобновления,
  разрешения и поиска SKU, инкремента сканированием, записи итогового
  количества, удаления строки, проведения и удаления черновика.
- Использовать `MobileCommandReceipt` для каждой изменяющей мобильной команды.
- Дополнить V1-контракты устойчивыми problem codes и данными для прямого UI.

## 4. Мобильный процесс

- Добавить действие на главную страницу и группу страниц инвентаризации.
- Реализовать выбор склада, список незавершённых документов и сканирование
  ячейки.
- Реализовать один наглядный рабочий экран: инструкция/ввод сверху, действия до
  списка, строки и расхождения в общем вертикальном скролле.
- Переиспользовать автоматический выбор аппаратного сканера и камеры, ручной
  поиск и проверенные правила фокуса/клавиатуры.
- После проведения показать итог и вернуться к списку документов.

## 5. Замена веб-процесса

- Изменить создание: склад и свободная ячейка обязательны до появления
  документа.
- Заменить многоячеечный редактор одной таблицей содержимого выбранной ячейки.
- Добавить накопление сканированием, ручной ввод итога, неожиданный товар, явный
  ноль, проведение и удаление черновика через общий command service.
- Сохранить историческое чтение старых проведённых документов.

## 6. Проверка и приёмка

- Собрать всё решение и проверить EF model drift без тестов.
- Применить миграцию к локальной базе после проверки её состава.
- Вручную проверить пустую и непустую ячейки, ожидаемый и неожиданный товар,
  явный ноль, повторное сканирование, поиск, возобновление после перезапуска,
  запрет движения, проведение, удаление черновика и конкурентные команды.
- После приёмки перенести постоянные правила в контекст, заморозить
  спецификацию и определить следующий мобильный процесс.
