# Модель данных: приемка, источники 1С и срок годности

Этот документ описывает целевые сущности и ограничения. Названия типов
ориентировочные; при реализации их можно согласовать с существующим кодом.
Бизнес-правила принадлежат [spec.md](spec.md).

## Источник 1С

| Сущность | Ключевые данные | Связи и ограничения |
|---|---|---|
| Документ-источник | Непустой `Ref_Key`, последнее успешно полученное состояние, версия, время успешной сверки, последняя ошибка | `Ref_Key` уникален; ошибка транспорта не заменяет успешную версию. |
| Версия документа | Ссылка на источник, время получения, полный исходный снимок | Новая версия возникает при изменении содержимого; прежние версии неизменяемы. |
| Проекция строки | Версия, исходный номер строки, распознанный SKU, количество либо причина невозможности расчета | Повторяющиеся SKU остаются отдельными строками; проекция пересчитывается после обновления справочника даже при прежнем исходном снимке. |
| Связь источника с WMS-ордером | Источник, ордер, время прикрепления и открепления | В один момент источник связан не более чем с одним ордером; история связей сохраняется. |

Проекция дает для известного SKU числовой вклад только тогда, когда все его
относящиеся к плану строки интерпретированы. Отсутствие строки и отключенный
источник дают известный ноль; ошибка разбора дает неизвестное значение, а
не ноль. При снятии проведения, пометке удаления или несовпадении склада
источника с ордером его текущий вклад равен нулю.

## Ордер WMS и приемная LPN

| Сущность | Ключевые данные | Связи и ограничения |
|---|---|---|
| Приходный ордер WMS | Собственный ID, склад, статус, активный цикл, ревизия, текущие план и факт | ID не равен `Ref_Key`; склад не меняется после создания. |
| Строка WMS-ордера | Ордер, SKU, план `decimal?`, факт `decimal?`, признак подтвержденного факта | Уникальна по ордеру и SKU; строку из справочника 1С может добавить оператор при подтверждении выбора в Mobile или менеджер в Web. Без вклада источников ее план равен `0`; до проверки факт `null`, явное подтверждение нуля дает факт `0` без движения. Проверка сохраняется при изменении плана и удалении последней LPN. При появлении SKU в источнике обновляется та же строка; известная строка не удаляется при исчезновении из 1С. `null` плана и `0` различаются. |
| Цикл приемки | Ордер, номер цикла, место приемки, начало, завершение, снимок плана и факта и ссылки на версии источников при завершении | Каждый повторный запуск создает новый цикл; прежние снимки неизменяемы. |
| Участник цикла | Цикл, пользователь, время присоединения | Один пользователь может присоединяться заново в следующем цикле; уникальность по циклу и пользователю. |
| Приемная LPN | Код, ордер, цикл, исходное место приемки, создатель, закрывший, статус | Одна активная позиция с одним SKU и датой; закрытую LPN не возобновляют. Отмена открытой LPN сохраняет историю без движения. |
| Позиция LPN | SKU, `DateOnly?`, действующее количество `decimal(15,3)` | Дату требует актуальный флаг SKU при закрытии положительной позиции; количество меняется после закрытия только до первого размещения. |
| Размещение LPN | LPN, исходное место приемки, адрес хранения, SKU, дата, количество, ссылка на движение | Каждое подтвержденное размещение проводится отдельно и сохраняет происхождение. |

Удаление закрытой LPN оставляет строку и исходные операции для истории, отмечает
ее недействующей и обнуляет ее вклад в факт ордера. После первого размещения
количество позиции LPN не исправляется. Поправка до размещения проводится в
исходном месте приемки и не меняет SKU или дату.

## Складской учет и аудит

| Сущность | Ключевые данные | Связи и ограничения |
|---|---|---|
| SKU | Импортируемые реквизиты и местный флаг учета срока | Синхронизация 1С не перезаписывает местный флаг; его изменение аудируется. |
| Остаток | Склад, ячейка, SKU, `DateOnly?`, подписанное количество | Уникален по всем четырем измерениям, в том числе для неизвестной даты; отрицательный итог возможен после удаления LPN. |
| Движение | Источник, назначение, SKU, дата, положительное количество, регистратор, LPN при собственном движении, ссылка на обращаемое движение | Обратное движение сохраняет величину, дату и адреса исходного при обратном направлении. Исходное движение обращается не более одного раза. |
| Оборот | Движение, адрес, количество до, изменение, количество после | Неизменяемая запись; отрицательные значения допустимы для обращения LPN. |
| Событие аудита | Тип, время, исполнитель или источник действия, затронутые IDs, значения до/после, ссылка на команду и движения | Пишется в той же транзакции, что бизнес-состояние; повтор команды не создает второе событие. |
| Квитанция команды | Пользователь, тип команды, request ID, результат | Существующий механизм идемпотентности сохраняется для новых команд. |

При удалении LPN обращаются только ее приход, поправки количества и
размещения. Любые движения других процессов остаются независимыми; правила
их нового проведения по датам определяются в последующих спецификациях.

Действующая инвентаризация хранит только SKU без даты. Ее расширение для
датированных и отрицательных остатков находится в отдельной задаче.
