# Инвентаризация по ячейке и сроку годности

**Ветка** `codex/018-inventory-count`

**Дата** 2026-11-22

**Статус** Реализовано. Сборка и складские тесты прошли, ручная приёмка Web и ТСД ожидается.

Инвентаризация приводит складские остатки к подтверждённому физическому факту. Сценарий охватывает «Комплектацию» и «Хранение» и заменяет прежнюю инвентаризацию в `Wms`.

## Пользовательские сценарии и проверка

### Сценарий 1. Пересчитать ячейку и провести факт (P1)

Оператор находит активную ячейку выбранного склада в Web или на ТСД, открывает черновик и пересчитывает товар. Это основной сценарий восстановления достоверных остатков.

1. При открытии свободной ячейки любой из двух зон создаётся один черновик со всеми ненулевыми учётными остатками. Повторное открытие возвращает тот же черновик с введёнными данными.
2. При учётном остатке `−2` и подтверждённом факте `0` проведение добавляет `+2`, итоговый остаток равен `0`. При наличии непересчитанной строки проведение отклоняется, а черновик сохраняется.
3. Оператор проводит все расхождения одним действием. Если ответ потерялся, повтор той же команды возвращает результат без новых движений. Выход со страницы сохраняет черновик и удержание, удаление черновика освобождает ячейку без движений.

### Сценарий 2. Сверить и уточнить сроки годности (P1)

Оператор сверяет срок на товаре с учётной группой и указывает количество для каждого обнаруженного срока. Он может внести дату, которая отсутствовала в учёте.

1. При учётных `5` без даты оператор подтверждает `3` с прочитанной датой и `2` с неизвестным сроком. После проведения учёт содержит две группы с соответствующими датой и количествами.
2. При учётных `5` с одной датой и фактических `5` с другой оператор ставит `0` для первой группы и подтверждает `5` для второй. Проведение списывает `5` из первой группы и добавляет `5` во вторую, сохраняя общий остаток SKU.
3. Когда в ячейке есть товар одного SKU с двумя читаемыми датами, оператор подтверждает количество для каждой из них. Просроченную дату он фиксирует с маркировки, а нечитаемую явно подтверждает как неизвестный срок.

### Сценарий 3. Разрешить смешение SKU для ячейки (P1)

Оператор может сохранить фактический состав смешанной ячейки в черновике. Менеджер решает, разрешить ли хранение нескольких SKU в этой ячейке.

1. При запрете смешения и факте с двумя положительными SKU проведение отклоняется. Черновик, его строки и удержание ячейки сохраняются.
2. Сотрудник с ролью `Manager` включает мульти-SKU отдельным действием в Web при открытом черновике. Оператор проводит тот же черновик, используя актуальное разрешение ячейки.
3. Если принято решение разложить товары по ячейкам, оператор удаляет черновик, чтобы освободить ячейку. После складских перемещений оператор начинает новый пересчёт с актуальных остатков.

### Граничные случаи

- Действующая блокировка, активный резерв отбора или неразрешённая недостача блокируют старт в ячейке. Две одновременные попытки старта создают максимум один черновик и одно удержание.
- Пустую ячейку можно пересчитать и провести без движений. Нулевые учётные группы не добавляются автоматически, но найденное количество для такой группы можно указать.
- Несколько сроков одного SKU считаются одним SKU для проверки смешения. Факт с одним SKU можно провести, когда остатки остальных учётных SKU подтверждены нулём.
- При изменении остатков после начала пересчёта проведение отклоняется целиком. Черновик и введённый факт доступны оператору.

## Требования

### Функциональные требования

- **FR-001** — `Operator` запускает, продолжает, редактирует, удаляет и проводит черновик в Web и на ТСД. Для проведения достаточно роли `Operator`, в том числе при расхождениях. `Manager` может просматривать документы и результаты в Web.
- **FR-002** — Документ охватывает одну активную операционную ячейку «Комплектации» или «Хранения» выбранного склада. При старте система проверяет занятость, удерживает ячейку целиком и фиксирует все ненулевые учётные остатки по SKU и сроку, включая отрицательные и группы без даты. Удержание исключает ячейку из других операций с остатками до проведения или удаления черновика.
- **FR-003** — Факт задаётся отдельно для каждой пары SKU и срока. Оператор может добавить обнаруженный SKU или группу, увеличить факт сканированием и задать количество вручную в основной единице SKU с точностью до трёх знаков после запятой. Факт неотрицательный. Оператор явно подтверждает ноль для учётной группы, которой физически нет.
- **FR-004** — Для положительного факта SKU с включённым учётом сроков оператор подтверждает фактическую дату либо явно выбирает неизвестный срок. При наличии учётных дат скан SKU сам по себе не распределяет количество по срокам. Отдельные датированные группы сохраняются и у SKU с выключенным признаком учёта сроков. SKU без требования срока и без датированных групп можно посчитать в группе без даты обычным сканированием.
- **FR-005** — Проведение сверяет актуальные остатки с исходным учётным снимком, требует факт по каждой учётной группе и проверяет действующее разрешение смешения по итоговому составу ячейки. Для каждой ненулевой разницы проводится корректировка соответствующего SKU и срока. При успешном проведении движения, остатки, история, статус документа и освобождение ячейки фиксируются вместе. Ошибка оставляет учёт без частичных изменений, точный повтор успешной команды не создаёт повторных движений.
- **FR-006** — Включение и выключение мульти-SKU требует явной роли `Manager`. Действие доступно в Web, в том числе при открытом черновике. Выключение отклоняется, пока в ячейке есть ненулевые остатки более одного SKU. Топологию настраивает `Administrator`.
- **FR-007** — После переключения Web и ТСД используют замену для всех операций инвентаризации. Устаревшие сценарии, регистрации, маршруты, контракты и поля, замещённые новой инвентаризацией, удаляются. У каждого пересчёта один действующий путь проведения.

### Основные сущности

- **Документ инвентаризации** — склад, ячейка, состояние черновика или проведения, авторы действий и строки пересчёта.
- **Строка пересчёта** — SKU, дата либо отсутствие даты, исходное учётное количество и отдельно подтверждённое фактическое количество.
- **Удержание ячейки** — исключительное право открытого черновика на пересчёт этой ячейки.
- **Корректировка остатка** — проведённая разница по строке со ссылкой на инвентаризацию и записью в истории остатков.

## Критерии успеха

- **SC-001** — В каждой из двух зон оператор может открыть, продолжить и провести инвентаризацию через Web и ТСД. После проведения остаток каждой пересчитанной группы равен факту, включая исходный отрицательный остаток.
- **SC-002** — Приёмочные примеры с двумя датами, заменой даты, неизвестным сроком и просроченным товаром дают отдельные ожидаемые остатки без объединения групп.
- **SC-003** — Повтор успешного проведения добавляет ноль движений. Отклонённое проведение оставляет ноль проведённых изменений и сохраняет открытый черновик.
- **SC-004** — Смешанный факт в ячейке с запретом отклоняется. После включения мульти-SKU менеджером тот же черновик можно провести, сохранив все введённые количества.

## Допущения

- Переход выполняется на очищенной базе разработки. Формат старых черновиков, проведённых документов и контрактов не переносится. При изменении схемы переход оформляется миграцией.
- Инвентаризация — локальная складская операция Wms.
