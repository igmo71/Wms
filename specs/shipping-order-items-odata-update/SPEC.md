# Обновление табличных частей расходного ордера в 1С

## Результат

При переводе расходного ордера WMS в `ReadyForShipment` система корректно
передает в 1С итог фактического отбора. Табличные части передаются полностью,
без потери реквизитов, которые WMS не использует в своей предметной модели.

## Область и ограничения

- Изменение применяется только когда `FactQuantity` отличается от
  `PlanQuantity`.
- WMS не хранит снимок реквизитов строк 1С в доменной модели. Перед PATCH
  выполняется повторное чтение полного документа из 1С.
- Для MVP предполагается одна строка распоряжения на SKU. Несколько строк
  одного SKU по разным распоряжениям не поддерживаются.
- `ShippingOrderItem.Action` остается исходным импортированным значением и не
  используется как состояние итоговой строки 1С.

## Правила формирования

Перед PATCH WMS получает свежий `Document_РасходныйОрдерНаТовары` из 1С и
сравнивает его плановые табличные части с локальным WMS-планом. При отличии
составов строк, SKU или плановых количеств PATCH и смена статуса блокируются
как конфликт.

Для каждой локальной строки отгрузки:

- при `FactQuantity > 0` исходная строка `ОтгружаемыеТовары` получает действие
  `Отгрузить` и фактическое количество;
- при недоборе добавляется копия исходной строки с новым уникальным
  `LineNumber`, действием `НеОтгружать` и количеством `PlanQuantity -
  FactQuantity`;
- при `FactQuantity = 0` исходная строка становится `НеОтгружать`, а строки
  `Отгрузить` нет;
- в `ТоварыПоРаспоряжениям` остаются только строки с фактическим количеством
  больше нуля; их количество равно `FactQuantity`, а реквизиты распоряжения,
  характеристики, назначения и серий сохраняются.

В обеих табличных частях PATCH содержит все строки и все реквизиты, возвращенные
из 1С, включая упаковки и упаковочные листы. После успешного PATCH документ
переводится в `КОтгрузке` и проводится.

## Дополнительная проверка импорта

При импорте документа в статусе `Prepared` действия всех строк
`ОтгружаемыеТовары` должны быть `Отобрать`. Иное действие считается внешним
конфликтом: локальный документ не обновляется, устанавливается
`ExternalChangeDetected`, причина записывается в лог.

## Критерии приемки

- Полная, частичная и нулевая отгрузка передают корректные строки в 1С.
- PATCH не сбрасывает характеристики, назначения, серии, упаковки и упаковочные
  листы.
- Изменение плановых строк документа в 1С после начала работы в WMS блокирует
  передачу и проведение.
- Строки `ТоварыПоРаспоряжениям` с нулевым фактом не передаются.

## Открытый технический вопрос

Нужно подтвердить на тестовой базе 1С, должен ли реквизит `Ref_Key` строк
табличных частей присутствовать в PATCH. В полученном примере он отсутствует,
тогда как текущие интеграционные модели его содержат.
