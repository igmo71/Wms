# ТСД и Mobile V1

Используются текущие экраны, адреса запросов и идентификаторы команд. Таблица описывает изменения результата.

| Операция | Результат |
| --- | --- |
| «Начать сборку» | После успешной выдачи сборка доступна в работе. Повтор с тем же идентификатором запроса сохраняет выданные количества. |
| «Маршрут» и данные «SKU» с подпиткой | Шаги и «Доступно» рассчитаны из одних закреплений. Дефицит — часть оставшегося плана, для которой сейчас нет действующего шага. Обновление выполняет чтение. |
| Сканирование и выбор ячейки | «Взять» показывает количество, допустимое для данного шага или выбранного адреса. Сервер перепроверяет условия при подтверждении. |
| Подтверждение отбора | Состояние закреплений и подтверждённый факт обновляются вместе. Неуспешная операция сохраняет прежние количества. |
| Недостача | Ответ сканирования передаёт ожидаемый физический остаток группы в `ExpectedPhysicalQuantity` отдельно от доступного сборке количества. Команда недостачи использует ожидаемый физический остаток. |
| Подпитка | Ручной заказ сохраняется. После подтверждённого перемещения результаты следующего чтения учитывают закреплённое количество. |

Форматы сообщений 1С и действующие проверки источника сохраняются.
