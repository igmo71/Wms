# Contracts: Web и Mobile приёмка

Контракт описывает ожидаемое поведение после реализации [спецификации](../spec.md). Внутренний GUID сохраняется для адресации; отображаемый номер WMS — отдельный атрибут.

## Web: группа «Приёмка»

| Вход | Маршрут | Содержимое и действия |
|---|---|---|
| Документы 1С | `/receiving-sources` | Список свободных и привязанных документов; поиск по номеру 1С или `Ref_Key`; номер/дата документа, склад, отправитель, статус сверки, номер и ссылка на WMS ордер. Manager может выбрать свободные документы одного склада и создать WMS ордер. |
| Ордера WMS | `/receiving-orders` | Список только WMS ордеров; поиск по номеру WMS; номер, фактическое время, склад, статус, количество источников и расхождения. |
| Карточка WMS | `/receiving-orders/{id:guid}` | Номер WMS — заголовок, фактическое время — отдельное поле. План, факт, LPN, циклы и источники — отдельные читаемые разделы. |

Для Operator страницы доступны на чтение согласно текущей политике `Operator,Manager`. Manager имеет действия: создать ордер на странице 1С; сверить источники, изменить их состав, исправить/удалить допустимую закрытую LPN, завершить/открыть новый цикл на карточке. Видимость кнопок и серверные обработчики проверяют роль. На Web отсутствуют создание/заполнение/закрытие открытой LPN, фактический подбор SKU и подтверждение нулевого факта. Ошибка операции оставляет карточку доступной для обновления.

### Диалог «Изменить состав»

До открытия видны количество и номера связанных документов с последней сверкой; форма поиска скрыта. После открытия Manager выбирает прикрепление или открепление, ищет свободный документ по номеру/`Ref_Key` либо выбирает один из текущих, затем запрашивает предпросмотр.

Предпросмотр показывает номер документа 1С, склад, список только затронутых SKU с текущим и будущим планом, включая явное «неизвестно», и текст «Проведённый факт и движения сохраняются». Подтверждение доступно лишь после успешного предпросмотра. Оно отправляет `RequestId` и `StateToken`; при изменившемся состоянии возвращается конфликт «Данные изменились, обновите предпросмотр». Повтор неопределённого ответа с тем же `RequestId` сохраняет прежний результат. Успех закрывает диалог и перечитывает план, факт и связи. Условия другого склада, уже занятого источника или ошибки сверки показываются до выполнения либо в подтверждении понятным сообщением.

## Application: состав источников

| Операция | Вход | Результат |
|---|---|---|
| `PreviewReceivingOrderSourceChange` | `OrderId`, `SourceRefKey`, `Kind`, `UserId` | Реквизиты источника, склад, изменившиеся строки плана `Before/After`, `StateToken`, предупреждение о сохранении факта; ошибка при невозможной смене состава. |
| `ChangeReceivingOrderSources` для Web | существующие `RequestId`, `OrderId`, `SourceRefKey`, `Kind`, `Channel=Web`, `UserId` + обязательный `StateToken` | `OrderId` либо конфликт/ошибка доступа; команда сохраняет связь, план, аудит и receipt атомарно. |
| `ChangeReceivingOrderSources` для Mobile | существующий вход, `Channel=Mobile` | Прежний контракт и правила Mobile; Web маркер не требуется. |

Предпросмотр не заменяет проверку при записи. Команда сверяет авторизацию, склад, активную связь, версии и ревизию в существующей транзакции. Сверка 1С для прикрепления выполняется перед предпросмотром и действующая свежая проверка перед командой остаётся; изменившийся источник вызывает конфликт маркера. Отсутствующий источник, неуспешная сверка и неизвестный план различимы.

## Mobile V1: чтение ордера

`GET /api/mobile/v1/receiving-orders` и `GET /api/mobile/v1/receiving-orders/{orderId:guid}` возвращают тот же `MobileReceivingWorkOrderResponse` с дополнительными полями:

| Поле | Тип | Правило |
|---|---|---|
| `number` | string | Обязательный постоянный номер WMS формата `yyMMdd-HHmmss`. |
| `createdAtUtc` | DateTimeOffset | Фактическое время создания; клиент форматирует его для пользователя отдельно от номера. |
| `id` | Guid | Существующий внутренний ключ, сохраняется в маршрутах и командах. |

Ответ разрешения документа 1С, если содержит связанный `order`, использует тот же расширенный объект. Остальные команды Mobile и политика `Operator,Manager` не меняются. Клиент показывает номер на очереди и карточке; команды продолжают передавать GUID.
