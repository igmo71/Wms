# Проверка после реализации

Этот файл — инструкция разработчику для проверки нового Отбора и Подпитки. Сборки, тесты, запуск приложений и создание/применение EF миграции выполняет разработчик согласно `AGENTS.md`; агент проверяет сообщённые результаты и созданные файлы миграций.

## Подготовка

1. На тестовом складе подготовить два проведённых в 1С расходных ордера одного склада в статусе `Подготовлен`, с общим SKU; в WMS разместить этот SKU в нескольких ячейках с разными сроками. Для Подпитки подготовить полный поддон в Хранении и допустимую ячейку Комплектации.
2. Дать отдельным пользователям роли `Operator` и `Manager`; проверить, что роль `Administrator` сама не открывает решения Manager.
3. Разработчик создаёт миграцию новой схемы. Агент проверяет внешние ключи, точность количества, уникальность активных ограничений и отсутствие случайных изменений других процессов. Проект в разработке, перенос незавершённых старых сборок не требуется.

Минимальные команды разработчика после реализации:

```powershell
dotnet build Wms.slnx -nologo -v:minimal
```

Для тестов конкретного инкремента использовать фильтр с именами реализованных проверок. В результате запуска проверить число выполненных тестов.

## Сквозные проверки

| Сценарий | Ожидаемый результат |
|---|---|
| Скан свободного РО 1С, добавление второго, начало | Один РО WMS с двумя источниками; оба переведены в `КОтбору`; при сбое одного физический Отбор закрыт до успешного повтора. |
| Отбор общего SKU из разных ячеек/сроков | Маршрут отдаёт приоритет FEFO, скан другой допустимой ячейки заново проверяется; резервы не меняют остаток до закрытия. Второй сотрудник не может взять зарезервированное количество. |
| Заказ и выполнение Подпитки | Очередь учитывает тип очереди и время; скан источника удерживает ячейку; подтверждение назначения немедленно переносит группу со сроком и делает её доступной сборщику; возврат поддона снимает удержание без второго движения. Повтор команды не дублирует перенос. |
| Изменение 1С после начала и решение руководителя | План WMS остаётся прежним. Операторское закрытие запрещено. Руководитель видит три состояния и либо меняет план с последующим физическим Отбором/возвратом, либо утверждает складской факт и распределение. |
| «Закрыть и отгрузить» с частичным и нулевым распределением | Исходные датированные группы списаны один раз напрямую, без остатка зоны отгрузки; сумма распределений равна факту, нулевой документ получает `НеОтгружать` и пустую таблицу распоряжений. Повтор закрытия не создаёт движения. |
| Сбой PATCH или POST одного РО 1С | Складской факт и обмен другого документа сохранены; ТСД и Web показывают стадию и ответ по проблемному документу. Повтор той же кнопкой пропускает подтверждённые документы. Повтор читает 1С, не затирает новую правку и не списывает товар ещё раз. |
| Собственный резерв при закрытии | При остатке 10 и факте 10 свободно для нового Отбора 0. Закрытие проводит 10 по собственному резерву. Повтор оставляет один результат списания. |
| Снятие проведения в 1С | При сохранении строк и статуса КОтбору отменить проведение одного РО 1С. Закрытие блокируется у обоих участников до восстановления источника. |
| Подтверждение POST | Для изначально проведённого РО принять PATCH и вернуть ошибку POST. Совпавшие строки и прежний признак проведения оставляют обмен в ошибке. После нажатия той же кнопки закрытия проверить повторный POST только неподтверждённого документа и единственное списание WMS. |
| Недостача, исправление факта и отмена | Недостача блокирует спорную группу без изменения учётного остатка. Manager проводит отдельную коррекцию или снимает ошибочный блок. Уменьшение факта требует скан исходной ячейки; отмена ждёт нулевого факта и завершения начатой Подпитки. |

На стенде 1С проверить прямой статус «Отгружен», все строки «НеОтгружать», последовательное заполнение строк одного SKU и повтор POST после потери ответа той же кнопкой «Закрыть и отгрузить». If-Match не поддерживается по проверке пользователя, внешняя гонка между GET и PATCH принимается.

## Проверка ТСД и Web (T065)

Используйте тестовую базу после миграций. Для каждого отклонения запишите номер сборки WMS, экран, действие и видимый результат; для обмена с 1С дополнительно нужны данные из раздела T061. Если стенд 1С недоступен, отметьте сценарии, которые невозможно довести до конца, отдельно от проверенных экранов и складских команд.

| Проверка | Ожидаемый результат |
|---|---|
| Вход и права | Кнопка «Отбор» на ТСД и пункт «Отбор» в Web открывают новые сборки. Operator работает со своими заданиями; Manager видит и решает расхождения в Web. Один Administrator без роли Manager не получает право решения. Старые экраны «Отгрузка» недоступны из навигации. |
| Сканирование и возврат навигации | В карточке SKU скан допустимой ячейки показывает её группу и требует явного подтверждения количества; чужая ячейка проверяется сервером. После перехода назад и повторного открытия карточки маршрут и факт читаются с сервера, старый запоздавший скан не выполняет действие. Скан палета или зоны отгрузки для обычного Отбора не требуется. |
| Неопределённый ответ при Отборе | Прервать связь после отправки подтверждения количества и до ответа. Повторить действие с тем же сохранённым ClientRequestId; факт и резерв появляются один раз. После достоверного ответа следующее действие получает новый ID. |
| Передача сборки | Передать уже начатую сборку другому Operator через Web. Новый ответственный видит текущий факт и маршрут; прежний не может продолжать изменение. Исполнители ранее подтверждённых записей не меняются. |
| Ожидание Подпитки | Заказать Подпитку из карточки SKU. Сборщик видит частичный и полный прогресс отдельного задания; подпитчик видит приоритетную очередь. После подтверждения назначения перенесённое количество доступно для Отбора, даже если палет ещё ожидает возврата; возврат палета не создаёт второго движения. |
| Одна кнопка закрытия | Нажать «Закрыть и отгрузить» для готовой сборки; после закрытия при ошибке обмена та же кнопка повторяет только неподтверждённые документы. Складское списание остаётся единственным; по каждому РО 1С видны стадия и ошибка. |
| Повтор обмена другим оператором | Закрыть сборку одним Operator, оставить один РО 1С с ошибкой обмена и войти другим Operator того же выбранного склада. Закрытая сборка видна в Web и ТСД; второй оператор может повторить обмен без нового складского списания. В результате закрытия и аудите остаётся первый сотрудник. |
| Возврат и отмена | Уменьшить подтверждённый факт только после скана исходной ячейки. Отмена требует нулевого факта; начатая Подпитка и возврат статусов РО 1С отображаются как незавершённые, пока операции не закончены. |

## Проверка обмена с 1С (T061)

Для каждого сценария сохраните номер РО 1С, результат в WMS и результат чтения документа в 1С. Между повторными нажатиями обновляйте карточку сборки. Используйте тестовый стенд и отдельные сборки: закрытый складской факт нельзя исправить простым повтором обмена.

| Сценарий | Действия | Ожидаемый результат |
|---|---|---|
| Прямая отгрузка | Закрыть полностью отобранный РО WMS; прочитать РО 1С после обмена. | PATCH сразу устанавливает `Отгружен` и целевые строки без промежуточного статуса отгрузки; POST подтверждает проведение. WMS показывает «Обмен подтверждён». |
| Нулевое распределение одного документа | Связать два РО 1С, физически отобрать количество только первого, утвердить распределение второго как ноль и закрыть. | У второго РО 1С все применимые строки `НеОтгружать`, `ТоварыПоРаспоряжениям` пусты, статус `Отгружен`, документ проведён. В WMS нет списания на его нулевую долю. |
| Несколько строк одного SKU и распоряжений | Подготовить один РО 1С с двумя строками общего SKU по разным распоряжениям; отобрать часть общего количества, требующую заполнения обеих строк. | WMS заполняет строки в исходном порядке: первую до исходного количества, остаток во вторую; неотгруженная часть остаётся `НеОтгружать`. Ссылки на соответствующие распоряжения сохраняются. |
| Отказ проведения после принятого PATCH | На тестовом обмене принять PATCH, вернуть отказ на `/Post` для одного из двух РО 1С; затем убрать отказ и повторить «Закрыть и отгрузить». | WMS показывает ошибку только этого РО; его стадия ожидает POST, другой РО подтверждён. Повтор читает 1С, не повторяет PATCH достигнутой цели, выполняет POST только неподтверждённого РО и не создаёт второго складского списания. |
| Потеря ответа POST | На тестовом обмене разорвать ответ `/Post` после обработки запроса в 1С; повторить ту же кнопку. | WMS сначала показывает неопределённый результат этого РО. Повтор читает его: если 1С уже подтвердила проведение и целевые строки, WMS завершает обмен без второго POST; если проведение не произошло, повторяет только POST. Складской факт и распределение не меняются. |

Если любой результат отличается, приложите номер РО 1С, стадию и ошибку WMS, статус/признак проведения и строки РО 1С после чтения. Это достаточно для разбора без изменения складского факта.
