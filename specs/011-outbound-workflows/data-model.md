# Модель данных планируемого процесса

Обозначения здесь логические; окончательные имена классов и таблиц выбираются при реализации. Связи и инварианты следуют [спецификации](spec.md). Существующие движения, обороты, остатки и аудит WMS остаются авторитетными записями складского учёта.

## Сборка и источники

Для реализации приняты имена `PickingAssembly`, `PickingAssemblySourceLink`, `PickingAssemblyPlanLine`, `PickingEntry`, `PickingAllocation`, `PickingClosure`, `ShippingExchangeTarget`. Общие ограничения представляют `PickingReservation`, `StockShortage` и существующий `StorageLocationLock`. Подпитка использует `ReplenishmentTask`, `ReplenishmentSourceCycle`, `ReplenishmentTransfer`. В записи переноса TaskId и SKU определяются через цикл и задание. Отдельные дубли этих полей не хранятся.

Сборка имеет отдельный ключ. Имена полей владельцев для новых сущностей — `PickingAssemblyId`, `PickingEntryId`, `ReplenishmentTaskId`. Типизированный `StockShortageOrigin` указывает на сборку либо задание. Резерв использует PickingEntryId как свой первичный ключ. Активный блок недостачи уникален по группе склад–ячейка–SKU–срок, включая null. В циклах Подпитки разрешён один незавершённый источник на задание. Проведённый шаг уникально ссылается на движение.

| Сущность | Существенные поля | Связь и ограничения |
|---|---|---|
| **РО WMS / сборка** | `Id`, человекочитаемый номер, `WarehouseId`, `Status`, `Revision`, создатель/текущий ответственный, время начала/закрытия/отмены, решение о закрытии | Собственный ключ, отличный от `Ref_Key` 1С. Статус: черновик → подготовка начала → в работе → закрыт или отменён. Подготовка начала фиксирует набор источников и план по каждому и блокирует физический Отбор до результата всех переходов 1С. |
| **Источник РО 1С** | `Ref_Key`, текущие строки и реквизиты, версия/время снимка, результат проверки | Существующий импортируемый документ. Данные источника read-only для Web; после начала не меняют план WMS автоматически. |
| **Связь сборка–источник** | `AssemblyId`, `SourceRefKey`, время, автор, состояние связи | Один активный источник принадлежит не более одной сборке, включая ожидающую отмену/обратный обмен. До начала можно открепить; после попытки начала — нельзя. Все источники одного склада. История откреплений сохраняется. |
| **План WMS по источнику** | `AssemblyId`, `SourceRefKey`, `SkuId`, `Quantity` | Неотрицательные количества с точностью до 0,001; уникальная строка по документу и SKU. Общий план — сумма по связанным документам. Для формирования обеих таблиц PATCH сохранять реквизиты исходных строк и распоряжений, включая строки, которые руководитель решил восстановить после удаления в 1С. После начала меняется только явным решением Manager. |
| **Попытка начала по источнику** | `SourceRefKey`, ожидаемый и проверенный статус, стадия, ошибка, время | Позволяет повторять лишь не завершённые переходы в `КОтбору`; частичный успех не допускает Отбор. |

Снимок для просмотра источника и версия, которую руководитель рассмотрел, сохраняются как данные проверки/аудита. Они не образуют четвёртый «план»: для решений остаются ровно план WMS, факт WMS и текущие данные 1С.

## Физический Отбор и доступность

| Сущность | Существенные поля | Связь и ограничения |
|---|---|---|
| **Запись Отбора** | `Id`, `AssemblyId`, исходная ячейка, `SkuId`, nullable `ExpirationDate`, подтверждённое количество, исполнитель и время, ревизия | Факт WMS до закрытия — сумма активных записей. Срок соответствует учётной группе; `null` не превращается в известную дату. Уменьшение требует скан исходной ячейки и подтверждение физического наличия освобождаемого количества. |
| **Количественный резерв** | `PickEntryId`, `AssemblyId`, группа остатка, активное количество | Совпадает с действующим подтверждённым фактом. Не имеет TTL. Освобождается при подтверждённом уменьшении либо завершается вместе со списанием при закрытии; не создаёт движения сам по себе. Уникальные ключи и ревизии защищают повтор. |
| **Удержание ячейки** | `WarehouseId`, `LocationId`, тип владельца, `OwnerId`, исполнитель, причина, начало/освобождение | В одной ячейке не более одного активного эксклюзивного удержания. Прямой палетный Отбор или снятый для Подпитки поддон удерживает всю ячейку, включая другие SKU. Владелец может завершить своё действие; другим операциям адрес недоступен. |
| **Блок недостачи** | группа `(WarehouseId, LocationId, SkuId, ExpirationDate)`, сборка/задание, учётное и обнаруженное количество, причина, исполнитель, время, решение/движение | Исключает спорную группу из новой работы, не меняя остаток до решения Manager. Живёт независимо от удержания ячейки; снятие через коррекцию или мотивированное решение без движения. |

`InventoryBalance` сохраняет учётное количество по четырёхчастному ключу и `RowVersion`; `StorageLocation.OperationalRevision` защищает состояние ячейки. Для нового выбора свободное количество группы равно учётному минус активные резервы минус заблокированное спорное количество, с исключением всей ячейки для не-владельца удержания. При блокировке всей группы её доступность ноль. Проверка и запись резерва/удержания выполняются в одной конкурентно защищённой операции, включая случай отсутствующей строки; экранные значения остаются подсказкой до подтверждения команды.

## Подпитка

| Сущность | Существенные поля | Связь и ограничения |
|---|---|---|
| **Задание Подпитки** | `Id`, `AssemblyId`, `SkuId`, заказанное/проведённое количество, время заказа, статус, исполнитель, рекомендуемые адреса | Предложения вычисляются маршрутом; лишь явное подтверждение создаёт заказ. Очередь: актуальный высший тип очереди среди документов сборки, затем первоначальное время запроса. До скана источника заказ может отмениться; после — остаётся до полного исполнения и завершения поддонов. |
| **Цикл источника** | `TaskId`, просканированная ячейка Хранения, время удержания, способ завершения и время | Источник выбирается фактическим сканом, а не фиксируется рекомендацией. В каждый момент активное удержание относится к фактически снятому поддону. Завершение требует повторного скана этой ячейки и подтверждения возврата остатка либо физической пустоты. |
| **Шаг переноса** | `TaskId`, цикл источника, ячейка Комплектации, `SkuId`, `ExpirationDate`, количество, `MovementId`, исполнитель, время | Один подтверждённый шаг переносит одну датированную группу и публикует её в целевой ячейке в той же транзакции. Несколько сроков — несколько шагов FEFO. Остальные SKU на поддоне не меняются. Проведённый шаг не редактируется; исправление — новое связанное движение Manager. |

Состояния задания для подпитчика различают заказано, работа с источником, количество добавлено/поддон ещё снят, завершено; экран сборщика сводит их к предложено/заказано, выполняется, пополнено. Начатая Подпитка может пережить закрытие сборки, но ожидающая отмена незакрытой сборки ждёт её завершения. Вновь рассчитанная потребность не создаёт автоматически дубль заказа.

## Закрытие и обмен

| Сущность | Существенные поля | Связь и ограничения |
|---|---|---|
| **Распределение факта** | `AssemblyId`, `SourceRefKey`, `SkuId`, количество | Сумма по документам для SKU строго равна проведённому факту WMS. По каждому документу количество не выше утверждённого плана WMS. Общий SKU при недоборе требует решения Manager; ноль допустим. Срок конкретному документу не назначается. |
| **Результат закрытия** | `AssemblyId`, кто/когда/какое решение, проверенные версии источников, идентификаторы движений | Один неизменяемый складской итог. Для положительных записей создаются исходящие движения из первоначальных ячеек с их сроками; для общего нуля — ни одного движения. Повтор возвращает тот же результат. |
| **Цель обмена по РО 1С** | `SourceRefKey`, версия рассмотренного источника, целевые строки `Отгрузить/НеОтгружать`, статус `Отгружен`, стадия PATCH/POST, ошибка и время, ревизия решения | Каждый документ синхронизируется отдельно. Повтор кнопкой закрытия обрабатывает только неподтверждённые документы по сохранённым целям. Одновременные попытки одного документа сериализуются. Пустые `Товары по распоряжениям` допустимы при нуле. Новая правка 1С после рассмотренного состояния переводит цель в ожидание нового решения; WMS факт не меняется. |

После закрытия `PickEntry` и движения сохраняют исходные ячейки/сроки, а `Allocation` отвечает только за количества документов. Учётного остатка зоны отгрузки нет. История не стирается при исправлении или сбое обмена.

## Атомарные границы и проверки БД

- Создание связи защищено уникальностью активного `SourceRefKey`; обе параллельные попытки не могут присоединить один РО 1С к разным сборкам.
- Подтверждение Отбора, освобождение факта, удержание ячейки, сообщение о недостаче и решение Manager сохраняются вместе со своим состоянием, аудитом и квитанцией команды. Новые резервы не превосходят доступный остаток даже при параллельных запросах.
- Подтверждение назначения Подпитки сохраняет шаг, движение, оба остатка, обороты, прогресс задания, аудит и квитанцию. Скан возвращённого/пустого источника снимает лишь его удержание и также выдерживает повтор.
- Закрытие сохраняет все исходящие движения, остатки, обороты, завершение резервов, распределение, цели обмена и решение в одной транзакции. PATCH/POST не входят в эту транзакцию.
- Все количества имеют точность 0,001; нулевой шаг движения не создаётся. Срок, ячейка, склад и SKU фиксируются по учётной группе, не выводятся из визуального названия палета.
