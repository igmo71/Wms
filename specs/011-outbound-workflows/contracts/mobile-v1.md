# Mobile V1: Отбор и Подпитка

Контракт новых рабочих мест ТСД под `/api/mobile/v1`. Имена URL ниже — проектируемые; при реализации они заменяют старые `/shipping-orders` и проверяются по фактической маршрутизации. Все команды требуют явной роли `Operator`, активного склада и `ClientRequestId` (`Guid`). Повтор с тем же идентификатором и тем же содержимым возвращает ранее зафиксированный результат; другой ввод с тем же ID — конфликт. Для следующего физического действия создаётся новый ID. Неуверенный ответ сохраняется на экране для явного повтора.

## Чтение

DTO Отбора группируются в `Wms.Contracts/Mobile/V1/MobilePickingContracts.cs`, Подпитки — в `MobileReplenishmentContracts.cs`. Прикладные команды размещаются в `Wms.Application/Picking/` и `Wms.Application/Replenishment/`. Каждый именованный исполнитель использует существующий `Wms.Application.CommandExecution.CommandExecutor`, семантический хеш входа, аудит и квитанцию. HTTP endpoint преобразует скан документа в Ref_Key до вызова сценария. Чтение текущего источника и запись 1С принадлежат `ShippingSourceReader` и `ShippingSourceWriter` в `Wms.Integration/OneS/`. Протокол и отображение ошибок следуют существующему Mobile V1.

| Метод | URL | Результат |
|---|---|---|
| GET | `/picking-assemblies?warehouseId=...` | Незакрытые сборки создателя и закреплённые за работником, а также все закрытые сборки выбранного склада с неподтверждённым обменом: номер, состояние, документы 1С, прогресс по строкам и предупреждения. |
| POST | `/picking-assemblies/sources/resolve?warehouseId=...` | Скан десятичного штрихкода РО 1С без складского изменения; вернуть существующую сборку или свободный подготовленный источник. |
| GET | `/picking-assemblies/by-source/{sourceRefKey}?warehouseId=...` | Найденная сборка или свободный подготовленный источник для создания; без побочного действия. |
| GET | `/picking-assemblies/{id}?warehouseId=...` | План WMS, факт WMS, текущий вид источников и статус начала/закрытия. |
| GET | `/picking-assemblies/{id}/sku` | Общий список SKU: план, факт, ожидаемая Подпитка, состояние; кнопка «i» здесь отсутствует. |
| GET | `/picking-assemblies/{id}/route` | Рекомендуемые шаги по FEFO и адресу, доступные группы, признак недостачи; пересчитываемая версия, а не обязательная последовательность. |
| GET | `/picking-assemblies/{id}/replenishments` | Полный список предложенных и заказанных подпиток с состояниями для сборщика. |
| GET | `/replenishment-tasks?warehouseId=...` | Очередь подпитчика по типу очереди и исходному времени запроса; состояние поддона и проведённое количество. |
| GET | `/replenishment-tasks/{id}` | SKU, заказ/проведение, рекомендуемые и фактические адреса, группы срока, история шагов. |
| GET | `/sku/{skuId}/locations?warehouseId=...` | Доступное количество по ячейке и сроку; учётное количество показывается при отличии. Только чтение. |

Все экранные количества — снимок для выбора. Физическая команда заново проверяет доступность, FEFO, склад, адрес и состояние задания. Ошибки возвращают понятную причину и актуальную ревизию; клиент обновляет экран без потери подтверждённого факта.

Для карточки Отбора чтение по сборке, SKU и просканированному адресу возвращает допустимые группы, предлагаемое количество или причину отказа. При чужом SKU показываются адрес и фактические SKU. Оператор подтверждает количество отдельным действием.

## Команды Отбора

| Метод | URL | Ввод и результат |
|---|---|---|
| POST | `/picking-assemblies` | Скан свободного `SourceRefKey`, создание сборки с первым документом. Возвращает `AssemblyId`. |
| POST | `/picking-assemblies/{id}/sources` | Скан и присоединение другого свободного РО 1С того же склада до начала. |
| DELETE | `/picking-assemblies/{id}/sources/{sourceRefKey}` | Открепление до начала; последний источник отменяет пустой черновик с историей. Тело содержит `ClientRequestId` и выбранный `WarehouseId`. |
| POST | `/picking-assemblies/{id}/start` | Зафиксировать источники и запустить переходы `КОтбору`; вернуть состояние по каждому документу. При потере ответа клиент повторяет тот же запрос. После полученного результата о частичном успехе действие «Повторить начало» создаёт новый ClientRequestId для той же сборки и продолжает оставшиеся переходы. |
| POST | `/picking-assemblies/{id}/take-over` | Явное принятие начатой сборки от другого сотрудника. История исполнителей факта сохраняется. |
| POST | `/picking-assemblies/{id}/picks` | Подтвердить количество для просканированной ячейки, SKU и учётной группы срока. Вернуть факт, резерв и прогресс. Для палетной ячейки проверить удержание этой сборки. |
| POST | `/picking-assemblies/{id}/pallet-source` | После скана закрепить всю допустимую ячейку за сборкой перед снятием поддона. Удержание сохраняется при прерывании до ввода количества. |
| POST | `/picking-assemblies/{id}/pallet-return` | При отмене подтвердить сканом возврат поддона. Освободить адрес после подтверждённого возврата всего взятого из этой ячейки количества. При прерывании до первой записи факта достаточно подтвердить возврат поддона. |
| POST | `/picking-assemblies/{id}/picks/{pickId}/reduce` | Скан исходной ячейки, освобождаемое количество, подтверждение физического наличия в ячейке. Возвращает новый факт и доступность. |
| POST | `/picking-assemblies/{id}/shortages` | Явное сообщение о недостаче группы с ожидаемым/найденным количеством и необязательным пояснением; фактически взятое количество и его резерв фиксируются с сообщением один раз. Уже подтверждённый факт учитывается по ссылке на запись. |
| POST | `/picking-assemblies/{id}/close-and-ship` | Кнопка «Закрыть и отгрузить». Открытая сборка проходит проверки и складское закрытие. Закрытая сборка повторяет только неподтверждённый обмен с 1С по сохранённым целям. Вернуть стадии документов и причину ошибки. |
| POST | `/picking-assemblies/{id}/replenishments/order` | Явный заказ отдельной предложенной Подпитки по SKU, источнику, назначению, количеству и ревизии сборки; возвращает задание. |

После полученного ответа об ошибке обмена следующее нажатие создаёт новый ClientRequestId для попытки обмена. При потере ответа на саму команду сохраняется прежний идентификатор до выяснения результата. Сервер проверяет состояние сборки перед выбором ветви операции. Для закрытой сборки используется сохранённый факт, независимо от уже освобождённых резервов и исходных остатков. Одновременные попытки обмена одного документа сериализуются.

Операторское закрытие при расхождениях возвращает причины по документу и SKU без проведения. Частичный успех PATCH/POST не меняет закрытый складской итог и не превращает команду закрытия в повторное списание.

## Команды Подпитки

| Метод | URL | Ввод и результат |
|---|---|---|
| POST | `/replenishment-tasks/{id}/source` | Скан выбранной ячейки Хранения: проверить доступность/FEFO и удержать всю ячейку. С этого момента задание начато. |
| POST | `/replenishment-tasks/{id}/transfers` | Скан фактической ячейки Комплектации, SKU задания, группа срока и количество; провести один перенос и сразу показать его сборщику. Удержание источника остаётся. |
| POST | `/replenishment-tasks/{id}/source-completion` | Повторный скан того же источника и признак «остаток возвращён» либо «ячейка пуста»; освободить удержание без второго движения. При неполном заказе задание предлагает следующий источник. |
| POST | `/replenishment-tasks/{id}/shortages` | Зафиксировать физическую недостачу и отдельный блок спорной группы, не списывая её автоматически. |

Скан другого допустимого источника или назначения разрешён. Если перенос отклонён, задача и физически снятый поддон остаются видимыми, а движение отсутствует.
