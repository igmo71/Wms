# Граница обмена РО 1С

`Wms.Integration` читает и пишет расходный ордер через существующий OData адаптер. `Wms.Application` принимает складское решение; Web показывает документ 1С только для чтения. Один связанный РО 1С — одна независимая цель и состояние обмена.

| Шаг | Контракт |
|---|---|
| Входящее уведомление / GET | Обновить текущее представление `Ref_Key`, склада, статуса, операции, получателя, очереди, даты, направления и строк; не менять план начатой сборки. Отсутствующий/нечитаемый реквизит не заменять нулём. |
| Начало Отбора | Для каждого связанного документа подтвердить `Подготовлен` → `КОтбору`; сохранять результат по документу. Сборка готова к физическому Отбору только при успехе всех документов. |
| Проверка перед закрытием | Свежий GET всех источников. Проведение документа, склад, складская операция, статус `КОтбору` и отсутствие пометки удаления — жёсткие условия; строки/количества и получателя Manager может рассмотреть по правилам спецификации; очередь, дата и направление обновляют отображение. |
| Цель после складского закрытия | По документу фиксируются утверждённые строки `Отгрузить` и `НеОтгружать`, `Товары по распоряжениям` только для положительного распределения, статус `Отгружен`, а также рассмотренная версия источника. Нулевое распределение допускает все строки `НеОтгружать` и пустую таблицу распоряжений. |
| Запись при закрытии | PATCH передаёт только состав табличных частей и статус `Отгружен`. WMS читает `Posted` при GET. После изменения документа WMS вызывает POST к методу `/Post` для его перепроведения. |
| Повтор после PATCH | Для закрытой сборки кнопка «Закрыть и отгрузить» повторяет обмен по документам без подтверждённого успеха. Если строки и статус совпадают с целью, PATCH пропускается и выполняется POST. После потери ответа на POST разрешено повторное проведение. Успешный ответ POST завершает обмен документа. Успешные документы пропускаются. |
| Новое изменение | Не повторять старый PATCH автоматически. Хранить новые расхождения и требовать нового решения Manager. После закрытия неожиданная смена статуса допускает явное новое разрешение Manager, пометка удаления блокирует PATCH/POST до восстановления того же документа. |
| Ошибка | Сохранить причину и стадию каждого неподтверждённого документа. Показать их на ТСД и в Web рядом с кнопкой «Закрыть и отгрузить». Обычный повтор доступен оператору. Новые расхождения источника требуют решения руководителя. |

Распределённое на документ количество SKU заполняет его строки последовательно в исходном порядке. Для строки берётся минимум её утверждённого плана и ещё не распределённого количества. Плановый остаток строки оформляется как «НеОтгружать». Адаптер сохраняет реквизиты строки и её распоряжения. Например, план 3 + 7 и факт 8 дают «Отгрузить» 3 + 5 и «НеОтгружать» 2.

По проверке пользователя используемая 1С не поддерживает If-Match. На текущем этапе принимается возможность внешней правки между GET и PATCH. Перед записью выполняется свежая сверка. Прямой переход в «Отгружен» и обработка ошибок POST проверяются на стенде.
