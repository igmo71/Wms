# Implementation Plan: Навигация и карточки мобильной приёмки

**Branch**: codex/005-mobile-receiving-ui | **Date**: 2026-10-22 | **Spec**: [spec.md](spec.md)

## Summary

Разделить текущий экран ордера на самостоятельные экраны SKU и списка LPN, использовать уже отдельный экран документов 1С как третий раздел. Сохранить один процесс приёмки и явного повтора команды при переходах. Затем обновить карточки SKU, сортировку и короткие действия LPN. Изменение относится только к мобильной приёмке.

## Current structure and dependency

Сейчас Wms.Mobile/Pages/ReceivingOrders/ReceivingOrderReceivingPage.xaml показывает SKU и LPN как два переключаемых блока, а ReceivingOrderSourcesPage.xaml открывается отдельно и также используется при создании ордера. ReceivingOrderReceivingProcess хранит повторяемую команду; страницы получают его по цепочке навигации. Данные текущего плана и факта уже есть в ответах ордера и ручного поиска SKU.

Предыдущая функция с экраном документов 1С завершена и включена в ветку этой доработки перед реализацией первого инкремента.

## Design

### Экраны и переходы

- Сделать существующий экран ордера экраном списка SKU с однозначным названием. Вынести список LPN в отдельный экран. Экран документов сохранить отдельным; его режим создания до появления ордера остаётся специальным случаем.
- В существующем ордере дать каждому разделу одинаковую компактную строку переходов. Текущий раздел показать выбранным ненажимаемым элементом, а не обычной серой кнопкой недоступного действия.
- Между равноправными разделами использовать стандартный переход страницы и затем удалять предыдущий раздел из навигационного стека. После любого количества переходов системная кнопка «Назад» ведёт к списку ордеров. Дочерние страницы SKU и LPN возвращают в исходный раздел.
- Не менять стандартную высоту и оформление верхней системной строки; изменить только текст заголовков.
- Показывать номер созданного ордера на экране документов 1С. Кнопку входа в цикл подписывать «Начать» для ордера к поступлению и «Присоединиться» для ордера в работе.
- Вынести действующий процесс присоединения и выбора места в отдельный короткий экран, доступный из SKU, списка LPN и документов 1С существующего ордера. После успешного присоединения возвращаться в исходный раздел. Для уже идущего цикла не требовать нового выбора места. Во время ожидания повтора не разрешать уход с экрана присоединения.
- Передавать тот же экземпляр ReceivingOrderReceivingProcess между разделами и дочерними страницами. При неопределённом результате команды блокировать конфликтующие переходы, сохраняя прежние входные данные и идентификатор повтора.
- На экранах SKU и списка LPN принимать скан LPN встроенным сканером или камерой. Обработчик активен только у видимой страницы; скан SKU остаётся внутри открытого LPN. Существующие проверки поколения сканирования сохраняются.

### Карточки и данные

- В списках SKU ордера и ручного подбора сортировать на клиенте по видимому названию без учёта регистра. Для стабильного порядка использовать код и затем ID как запасной ключ. Отсутствующее имя показывать как код или ID.
- Карточки списка ордера и подбора компоновать с названием слева и доступными планом и фактом справа на отдельных строках. Убрать порядковый номер. Единицу измерения, где она доступна, показывать один раз для пары количеств.
- Для известного плана и проверенного факта единое правило: равенство — зелёный факт и мягкий зелёный фон ордера или рамка подбора; любое отличие — жёлтый факт и соответствующий фон или рамка. Непроверенный факт — красный знак вопроса и нейтральная карточка. Неизвестный план не окрашивать как совпадение или расхождение.
- Использовать цвета, читаемые в светлой и тёмной теме. Текстовые значения сохраняют смысл без цвета. Компоновку проверить на самом узком поддерживаемом устройстве.

### Действия

- В списке LPN открыть карточку тапом по ней. Отдельную кнопку «Открыть» убрать; «Разместить» сохранить отдельным действием, когда оно доступно.
- На открытом редактируемом LPN разместить «🔍 SKU», «Отменить», «Закрыть» в одну строку. Оставить имеющееся подтверждение, явно называющее проводку прихода. Для закрытого LPN показывать только подходящие действия.
- Убрать «Готово» с экрана документов. Пока первого ордера нет, оставить только создание сканированием; после успешного скана и создания сразу показать номер ордера и общие переходы SKU, LPN, 1С.

## Constitution check

- Складской факт и точка проводки не меняются; команды приёмки продолжают идти через существующий процесс.
- Новых проектов, слоёв, хранилищ, миграций и API по текущим данным не требуется. Небольшой общий форматтер состояния SKU допустим только если он устраняет дублирование между двумя карточками.
- Перед первым инкрементом нужна завершённая версия предыдущей функции с экраном документов.
- При каждом инкременте обновлять .specify/memory/current/clients.md; когда правило разделения экранов станет действующей конвенцией, отразить его в .specify/memory/architecture.md.
- По текущей политике UI-изменения не требуют новых автоматических тестов. Сборку, запуск и проверку на устройстве выполняет разработчик по точным командам и сценариям после каждого инкремента.

## Increment sequence

1. Разделы ордера, общий экран присоединения, заголовки, переходы, сканирование и сохранность повтора.
2. Компоновка и алфавитный порядок карточек SKU, текст и цвет состояния в списке ордера.
3. Компоновка и алфавитный порядок карточек ручного подбора с цветом рамки.
4. Компактные действия LPN, переходы по карточкам и удаление дублирующих кнопок.

Каждый инкремент должен оставлять работающий маршрут приёмки и иметь отдельную короткую передачу разработчику для проверки на устройстве. Автоматические проверки и запуск приложения агент не выполняет без отдельного запроса пользователя.
