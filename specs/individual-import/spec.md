# Импорт физических лиц из 1С

## Результат

WMS хранит локальную копию справочника 1С `Catalog_ФизическиеЛица`, чтобы впоследствии разрешать отправителей и получателей складских ордеров в единый `PartyInfo`.

## Объём

- Полный импорт получает весь небольшой справочник одним запросом к 1С и сохраняет его одним пакетным вызовом EF Core.
- Пакетное сохранение одним запросом определяет существующие записи и выполняет один `SaveChangesAsync`; параллельная и постраничная обработка не используются.
- Одиночный импорт обновляет физическое лицо или группу по уведомлению 1С.
- `Ref_Key` отображается в `Individual.Id`, `Description` — в `Name`, `DeletionMark` — в `DeletionMark`, `Parent_Key` — в `ParentId`, `IsFolder` — в `IsFolder`.
- Пустой `Parent_Key` и `Guid.Empty` отображаются в `null`.
- Группы сохраняются вместе с физическими лицами, но не должны разрешаться `PartyService` как допустимый отправитель или получатель.
- Физические лица и группы отображаются в UI единым плоским постраничным списком без визуализации `ParentId`.
- Страница поддерживает поиск по наименованию, сортировку, показ деактивированных записей и ручное обновление из 1С.
- Расширение `PartyService` и пакетный `PartyService.GetManyAsync` не входят в текущий объём.

## Критерии приёмки

- Полный и одиночный импорт возвращают `OperationResult` и передают ошибки получения данных из 1С.
- Отсутствующее поле списка или отсутствующая запись одиночного импорта считаются ошибкой; пустой список является допустимым результатом.
- GET endpoint запускает полный импорт и возвращает `502 Bad Gateway` при ошибке ответа 1С.
- POST endpoint принимает уведомление об изменении, а фоновый обработчик выполняет одиночный импорт.
- Схема БД содержит таблицу `Individuals` для всех полей доменной модели.
- Пользователь может открыть справочник «Физические лица», просмотреть его постранично и получить явное сообщение об успешном или неуспешном ручном обновлении.
- Значения `PartyType` соответствуют фактическим именам типов 1С OData вида `StandardODATA.Catalog_*`.
