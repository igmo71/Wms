# WMS — адресный склад с интеграцией 1С

WMS управляет складскими операциями от приёмки до отгрузки. Оператор сканирует товар
и ячейки на Android-терминале сбора данных (ТСД), а менеджер в веб-интерфейсе
сверяет план с фактом и разбирает расхождения. Справочники и документы приходят
из 1С. WMS ведёт остатки по складу, ячейке, товару и сроку годности.

Основные сценарии MVP уже работают. Для разработки и проверки есть отдельные
среды `dev` и `test`. При переходе со старой WMS можно загрузить топологию склада
и начальные остатки из Excel, проверить данные перед импортом и посмотреть
итоговый протокол.

## Что умеет WMS

- **Приёмка и размещение.** Оператор принимает товар по документам 1С.
  При закрытии LPN (метки грузовой единицы) WMS приходует товар в зону приёмки. Его
  можно размещать по ячейкам частями, пока приёмка заказа ещё идёт.
- **Отбор и пополнение.** WMS объединяет документы 1С в задание на отбор, строит
  маршрут с приоритетом ближайших сроков годности (FEFO) и предлагает пополнение
  из резерва. Оператор фиксирует недостачу на ТСД, менеджер разбирает её в браузере.
- **Отгрузка.** При закрытии задания WMS списывает фактически отобранный товар
  и передаёт результат в 1С. Статус обмена виден по каждому документу, а
  неудачную отправку можно повторить отдельно.
- **Инвентаризация и перемещения.** Ячейку можно пересчитать на ТСД или в
  браузере по каждому товару и сроку годности. При проведении WMS корректирует
  остатки по результатам пересчёта. Перемещения выполняются напрямую или через
  транзитную ячейку.
- **Контроль склада.** В веб-интерфейсе доступны остатки, история движений и
  отчёты о работе сотрудников. Права на операции зависят от роли пользователя.

## Как устроен складской учёт

- **План и история операций.** WMS хранит версии документов приёмки из 1С.
  После начала отбора изменения рабочего плана согласовывает менеджер.
  Корректировка остатка добавляет новое движение и сохраняет исходную операцию.
- **Защита от повторного проведения.** Движение, остатки, аудит и результат
  команды записываются в одной транзакции. Если ТСД потерял связь после
  проведения, повтор той же команды вернёт сохранённый результат.
- **Доступность товара.** При расчёте доступного остатка WMS учитывает резервы
  отбора, блокировки ячеек и зафиксированные недостачи. Остатки одного товара
  с разными сроками годности учитываются отдельно.

## Технологии

| Компонент | Реализация |
| --- | --- |
| `Wms.WebApp` | ASP.NET Core, Blazor с серверной интерактивностью, MudBlazor |
| `Wms.Mobile` | .NET MAUI для Android, встроенный сканер Urovo через ScanWedge, сканирование камерой через Google ML Kit |
| `Wms.WebApi` | ASP.NET Core, API для ТСД и отдельные точки интеграции с 1С |
| Серверное ядро | C# / .NET 10, EF Core, SQL Server, отдельные проекты для домена, прикладных сценариев, хранения и интеграции |
| Интеграция и проверка | 1С через HTTP/OData, Docker Compose и Caddy для тестовых сред, xUnit и SQL Server LocalDB для интеграционных тестов |

## Как я веду разработку с Codex

Я использую **Spec-Driven Development (SDD)** с **Spec Kit**. Начинаю со
складского сценария, бизнес-правил и критериев приёмки. Для крупных изменений
составляю технический план и делю работу на шаги, которые можно проверять по
мере готовности. Так я переработал отбор, пополнение и отгрузку.
[Спецификация](specs/011-outbound-workflows/spec.md) · [План](specs/011-outbound-workflows/plan.md) · [Задачи](specs/011-outbound-workflows/tasks.md)

Я задаю Codex границы задачи и даю ему контекст через инструкции в репозитории,
конституцию проекта и описание текущего поведения WMS. Агент помогает
разобраться в коде, найти противоречия в требованиях и реализовать изменения.
Бизнес-решения принимаю сам, проверяю код и провожу ручную приёмку в браузере
и на ТСД.
Автоматические тесты сосредоточены на рисках для складского учёта, например
двойном списании или одновременном изменении остатков в одной ячейке.
[Инструкции для Codex](AGENTS.md) · [Конституция проекта](.specify/memory/constitution.md)

Когда сценарий готов, я обновляю описание текущего поведения и сохраняю
спецификацию как историю решений. Например, для инвентаризации заранее описал,
как подтвердить отсутствие товара, учесть неизвестный срок годности и повторить
проведение, если ТСД не получил ответ.
[Спецификация инвентаризации](specs/018-inventory-count/spec.md) · [Действующие правила](.specify/memory/current/other-workflows.md#inventory-count)
